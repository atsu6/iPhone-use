# 手机屏幕侧边栏（0.2.0）

普通 WDA 插件提供 MCP App，使用时在 Codex 侧边栏展示手机屏幕。界面自上而下是三部分：状态胶囊、手机、工具栏。状态胶囊显示机型（来自本机设备列表的型号名，不显示手机名称或标识）和连接状态：Live、等待解锁、已暂停、未连接或连接中。手机以圆角 iPhone 外壳展示按原始比例缩放的画面，包含细金属边框、黑色玻璃边缘、边框内的听筒、顶部灵动岛与侧键装饰；屏幕内有边缘光效及点击 / 拖动圆形 cursor。工具栏有三个按钮：刷新、主屏幕、截图。界面跟随宿主的浅色 / 深色主题，没有输入框或其他操作面板；灵动岛只是静态外观装饰，不参与手机控制或模型观察。

widget 顶部与机型状态胶囊之间留白 28px；浅色主题的面板底色为极浅灰 `#f8f8f8`，状态胶囊和工具栏为白底、0.5px 的 `#ebebeb` 描边与轻微弥散阴影；深色主题继续使用宿主背景。

首次收到操作活动或有效的新手势后，光效持续显示，工具调用间隙与准备下一步时不闪灭。暂时缺帧、隐藏页面及短暂断连保留最后一帧和操作光效状态；隐藏时暂停动画。认证暂停、新流替换旧流或页面销毁会重置操作光效，其中新流只重置序号，旧画面保留到新帧到达；认证暂停和实际销毁会清除图像。它表示操作已经开始，不能证明模型正在思考、仍在执行或整项任务已经完成；cursor 只表示实际动作坐标。最终关键结果仍按实际返回证据验收。

设备在状态胶囊与工具栏之间的区域内额外缩小 4%。边缘光效沿屏幕圆角分布，在四边中段自然渐隐至透明，保留四角的柔光。形状来自一张遮罩图：脚本按实际尺寸和圆角半径画出向内模糊的圆角环、四角柔光和细亮边，再用横纵渐变一起淡出；只在布局变化时重画一次，柔边不需要实时滤镜。遮罩内是三层以天蓝为主、带少量紫与粉的静态渐变，另叠三层大小与亮度起伏的白色波浪点阵；颜色与波点独立交替改变透明度，再整体做缓慢的明暗呼吸。灵动岛按屏幕短边计算尺寸和位置，竖屏位于顶部中央，横屏位于左侧中央，摄像头与胶囊一起旋转。圆形 cursor 映射到原始画面坐标。

## 打开与工具边界

`wda_ready` 和 `wda_screen` 的 `_meta.ui.resourceUri` 关联同一个 `ui://` 资源。两者成功返回的工具结果都带稳定的 `_meta["openai/widgetSessionId"]="iphone-use-wda-screen"`，让支持此机制的 Codex 在同一聊天内复用已有面板，而非每次调用新开标签。setup 本身不关联 UI；重跑 setup 后的 READY，以及预览的 open / pause / resume 均使用同一会话标识，MCP 重连后也保持一致。标识不含设备或聊天数据；宿主按 host、聊天、server 与资源隔离，不复用其他聊天的面板。失败的工具结果不创建新 UI 会话。

资源使用 `text/html;profile=mcp-app`，声明可用 fullscreen 模式和 preferredDisplayMode；App 连接后在宿主支持时请求该模式。实际展示位置和默认打开行为由宿主决定，资源声明不是宿主已经渲染的证明。面板已打开时直接继续 setup 或手机任务，不为刷新再打开一份；需要重新打开已关闭的面板时用 `wda_screen()`，不必重复 READY。

| 工具 | 可见范围 | 用途 |
| --- | --- | --- |
| `wda_ready` | 模型 | 验证控制通道并关联默认屏幕资源；恢复中仍按返回状态处理。 |
| `wda_screen` | 模型 | 默认 `action="open"`；`pause` 停止并清空预览，`resume` 在用户明确完成接管后恢复。 |
| `wda_screen_frame` | 仅 App | 读取最新缓存帧、短时活动与 cursor 事件，不属于模型的观察接口。 |
| `wda_screen_action` | 仅 App | 工具栏的三个动作，由用户点击触发：`refresh`、`home`、`screenshot`。 |

目录共 19 个工具，其中模型可用 17 个，App 专用 2 个；skills 仍为 2 个。同名标准 MCP 注册保持完整模型绑定。手机屏幕 widget 由普通插件提供。

## 工具栏

三个按钮只响应用户自己的点击，模型看不到也不应调用 `wda_screen_action`：

- **刷新**：用户点击后断开并重新连接预览流，探测 WDA `/status` 与解锁状态。确认解锁时恢复点击时的暂停（包括旧版 unknown）；检查过程中发生的新暂停保留。它不重启 WDA 服务、不创建会话、不截图或执行手机手势。认证完成后用户可主动点击恢复画面，模型不能代调这个 App 专用动作。
- **主屏幕**：向手机发送一次 Home。它与模型的手机工具共用同一把操作锁：手机正在执行其他操作时不发送，提示稍后再试。发送后此前的输入焦点和续传令牌作废。
- **截图**：读取一张原分辨率截图，放进 Mac 剪贴板；图像文件只在复制期间存在，随后删除。

认证暂停期间主屏幕和截图不可用，服务端也会拒绝，避免在用户输入密码时截取或干预画面。每个动作完成或失败后，工具栏上方短暂显示一行提示。动作请求在读取线程直接处理，不排在长时间的手机操作后面。

## 画面与性能

1. 用户可见的 App 最多每秒调用 4 次 `wda_screen_frame`，读取服务端最新缓存；MCP 服务在读取线程直接应答，模型的工具调用进行多久都不影响预览刷新；带序号避免重复传送同一帧；缺帧或认证暂停降至每秒一次状态查询，失败时有界退避。桥接请求与握手 / 显示模式请求最多等待 3 秒，避免挂起一分钟。
2. 预览 worker 通过已有 `appium-ios-device` 建立到 iPhone 的 USB 连接，读取 WDA 独立 MJPEG 设备端口，默认 9100。usbmux 交接的 socket 可能处于暂停状态，HTTP parser 挂载后恢复读取。它不绑定新 HTTP 监听端口，不走 WDA 命令队列。
3. JPEG 解析有界，仅保留最新 JPEG 和它按需生成的 base64；只编码用户实际请求的帧，重复 JPEG 不产生新序号。同尺寸的新帧不重复计算外壳布局。图像只保留在内存，不写入截图文件或运行账本；坐标和短时活动是有界元数据，不包含密码或输入文本。
4. 它不轮询 `/screenshot`、`/source` 或 session，不新增 XML / 截图 / XCTest 操作请求，不持有手机操作锁。临时缺帧、流重连、请求失败或隐藏后切回时保留内存里的最后一帧，恢复后替换；从未取得画面时保留 iPhone 外壳，显示带轻微反光的黑色关闭屏幕和小字「未连接」；收到有效画面后替换占位。旧画面不表示手机未变化，不作为模型观察证据。不自动触发控制通道恢复。
5. App 隐藏、关闭或销毁后停止轮询。页面缓存的 pagehide 不永久销毁组件，pageshow / focus 唤醒拉流；桥接 close 后保留画面并重连。服务端 5 秒预览租约到期后关闭 USB worker，保留最后一帧在内存中供回到窗口时使用；认证暂停会停止采集并清除实际画面，不能等租约到期才暂停认证预览。

实际点击和拖动的 cursor 使用控制器已有的执行坐标与视口事件，不为获得坐标另发 WDA 查询。指示为中性灰色圆点，点击显示 1.6 秒，以轻微收缩、回弹、停留和淡出表现按下 / 松开；拖拽显示 1.6–2 秒，先在起点按下，再平滑移动并在终点回弹、停留后淡出。多个真实动作可短暂重叠显示，各自完成完整动画，避免连续动作把前一个指示截断；认证暂停、断流 / 换流、隐藏和销毁立即清理全部指示。视口到内部屏幕按比例映射，外壳不会引入坐标偏移；外壳与画面一起适应竖屏、横屏和窄侧栏，旋转后使用新帧尺寸。减少动态效果时显示静止的点击位置或拖拽终点，保留相同显示时间。

持续光效只由页面记住“本次已开始操作”，不延长服务端短时活动的有效期，不增加手机读取、帧轮询频率或控制请求。光晕、细亮边和点阵统一在四边中段渐隐至透明，保留四角的柔光。渐变、点阵和遮罩都是静态的：三张无缝点阵纹理中波点大小与亮度呈波浪起伏，独立以 4 秒周期交替淡入淡出；三层颜色渐变及整体呼吸以 8 秒周期缓慢变化。动画只改变各层的透明度，没有实时运行的 blur 滤镜，也不对渐变角度做动画；隐藏时暂停，减少动态效果时静止。Live 圆点和进行中的按钮同样只做透明度动画。拖动 cursor 使用 transform，避免每帧移动 left / top。发布构建去掉 SDK 包含整帧的 console.debug，保留 warning / error。当前没有整项任务完成事件，模型准备下一步时光效继续，直到上述认证暂停、新流或页面结束条件发生；不能把光效消失或保留当作任务完成依据。

## 更新后仍空白

更新安装只改变下一次启动的插件 / MCP 路径；已有聊天可能仍连接旧进程、显示旧 UI 资源。重新连接聊天，关闭旧“手机屏幕”页再调用一次 `wda_screen()`；无需重启 WDA 或重做 READY。

工具打开时立即返回缓存状态，首帧稍后由可见 App 拉取；初始 `frame_available=false` 不证明流故障。`paused=true` 则清除实际画面，保留黑色外壳占位与对应暂停提示；`pause_reason=device_locked` 显示「等待解锁」，实际解锁后成功 READY 会恢复同一次锁屏暂停。`authentication` / `unknown` 显示「已暂停」，模型等待用户实际完成后显式 resume。用户点击刷新是主动恢复预览的请求：重新连接 USB 预览并检查解锁，成功时可恢复点击时的任意原因暂停；检查期间新发生的暂停保持。旧版缺少暂停原因时保守按 unknown 处理。READY 的 `preview` 也返回原因；检查期间另一次暂停不会被旧检查解除。控制工具正常而预览一直空白时，应区分 App 连接和独立 USB 9100 流；不要循环 `/screenshot`、新建控制 session 或恢复 WDA 来掩盖预览故障。0.1.9 修复了真实 USB socket 暂停导致收不到帧的问题。

## 密码与 Face ID

看到真实密码、PIN、验证码或 Face ID 提示后，先 `wda_screen(action="pause")`，再必须调用宿主提问功能提示用户在手机上完成，首个选项固定「已完成继续」，并停止手机动作、观察和截图。暂停状态不会因重新打开预览或调用 READY 自动解除。可以整理已有结果，但不能轮询接管期间的画面。

只有用户实际选择「已完成继续」或明确通知完成后，才 `wda_screen(action="resume")`，获取一次新观察，按当前位置继续剩余工作。用户接管可能改变页面或完成提交，不沿用旧坐标和观察 ID，也不重放已完成操作。完整规则见 [认证接管](../skills/iphone-wda-use/references/authentication.md)。

widget 提供用户预览；模型不能把未返回给自己的缓存流当作观察证据。未知页面仍按下一步需要使用 `wda_observe` 或动作的 `observe` 输出，最终关键结果仍以实际返回的图像 / 树 / 记录验收，不增加每步验证。

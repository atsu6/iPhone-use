# 0.2.0 延迟优化

日期：2026-10-07（Asia/Shanghai）。历史实测里 83.6% 的任务墙钟时间在 WDA HTTP 之外，其中约 98% 属于模型链路。所以这一版不再只数 HTTP 请求，而是针对三件事：每一轮放进模型上下文的数据量、完成一步需要的模型回合数、少数会直接卡住任务的耗时陷阱。安全设计没有放松：不重放不确定的写操作、服务归属核验、封闭 schema、hittable 检查全部保留。

真机数据来自同一台 iPhone 17 Pro Max（iOS 26.7.1）在“设置”App 内的操作，没有更改任何设置；它们是单设备、少量样本，不是 p50 / p95，也不含模型时间。

## 每轮数据量

| 项目 | 0.1.14 | 0.2.0 |
| --- | ---: | ---: |
| 同一合成页面 99 个节点的一次观察 | 18,424 字节 | 6,868 字节 |
| 真机主屏幕 READY 的返回文本 | 20,538 字节 | 7,596 字节 |
| 真机“设置”页折算到每个节点（两次运行页面不同） | 约 206 字节 | 约 58 字节 |
| 工具目录中模型可见部分（17 个工具，Codex 投影） | 29,568 字节 | 21,419 字节 |
| 真机一张截图交给模型的内容 | 仅文件路径，无图 | 722×1568 JPEG，约 110 KB |

- **节点只保留一份事实。** `type` 去掉 `XCUIElementType` 前缀；`name` 与 `label` 相同只留 label；StaticText 的 `value` 与文字相同不再重复；`enabled` / `visible` / `in_viewport` 为 true 时省略；`rect` 是整数 `[x, y, width, height]`。每次观察里固定不变的提示文案移到工具说明，观察 ID 缩短到 12 位。`wda_find`、`scroll_find` 的结果和 `collect_list` 的行用同一格式，不再返回模型用不上的元素 ID。
- **截图真正送到模型。** Codex 0.160 在工具结果带 `structuredContent` 时只把它交给模型，`content` 里的图片块被丢弃（见其 `as_function_call_output_payload` 及测试 `preserves_structured_mcp_content`）。此前模型只拿到 `image.path`，要看图就得多一轮读图工具。现在面向模型的结果只有一个紧凑 JSON 文本块加图片块，不再带第二份结构化拷贝；只有 widget 自己读取的 `wda_screen` / `wda_screen_frame` / `wda_screen_action` 保留 `structuredContent`。
- **截图先在 Mac 上缩放一次。** WDA 的 `/screenshot` 固定返回原分辨率 PNG（真机历史 110 张平均 1,063 KB，最大 4,388 KB），而视觉模型会自己缩图，保留在上下文里的图每个回合都会重新上传。现在用系统自带 `sips` 缩到短边 ≤ 768、长边 ≤ 1568 的 JPEG（1320×2868 → 722×1568，实测约 65 ms），并返回精确的 `image.pixel_to_point`。原始 PNG 仍保存在同名 `.png`；`sips` 不可用或失败时退回原图，`WDA_IMAGE=original` 可关闭缩放。中文正文和说明文字在缩放后的图上清晰可读。
- **schema 文档只写一次。** selector 的字段说明只在 `wda_find` 完整出现，其他工具发布相同的封闭结构和一句指引；同一工具内重复的 selector / observe 用 `$defs` 引用。运行时仍用完整 schema 逐项校验，所有发布 schema 与运行时合同的等价性有回归测试。

## 模型回合数

- **目标消歧。** 同名元素叠在同一位置（例如一行和其中的文字）时，点最内层的中心等价于点其中任何一个，工具直接取最内层可点的元素；只有一个匹配在屏幕内时取它。真机上“通用”一行匹配 2 个元素，现在一次成功，此前是 `ambiguous_target`。多个分开的匹配仍然报错，但附带每个候选的 `index`、类型、位置、`tap` 坐标和 `hittable`，一轮即可修正。selector 新增 `label_contains` 和 `index`。
- **标签失败立刻改坐标。** selector 没有带来动作时（找不到、不唯一、被判定不可点、不可编辑、滚动查找用尽），错误结果直接附当前截图和坐标点，下一次调用就能按坐标完成，不需要先 observe 一轮，也不鼓励换标签写法重试。输入的对应做法是先按坐标点中输入框，再调用不带 selector 的 `wda_type_text`，文字进入当前焦点；安全输入框照旧拒绝并交给用户。hittable 检查本身没有去掉：是否越过它由看到截图的模型决定。
- **动作后的观察等转场结束。** 真机上点击后立刻读树，进入新页面的 9 次里 9 次读到的是两页混在一起的树（98 个节点，其中约 40 个属于上一页）。现在动作附带的树读取前让 WDA 等动画结束，空闲即返回，读完恢复为 0：上限设为 0.5 / 1.0 / 1.5 秒的 13 次全部读到干净的新页面，代价约 0.45 秒；默认上限取 0.8 秒。返回上一页时内容在各档下都一致，只有个别节点的位置随后微调。动作附带的纯截图没有这种等待机制，固定等 0.5 秒。`WDA_SETTLE_SECONDS=0` 可关闭。

## 耗时陷阱

- **长文本输入不再撞超时。** 输入按 30 字/秒进行，而单个请求只有 15 秒：约 450 字以上必然超时，并被标成不确定，只能回读、不能重放。真机 600 字在 0.1.14 上 15 秒后报 `action_uncertain`，手机仍在继续输入。现在文本按约 200 字一段依次发送，每段的超时按字数计算；第一段聚焦输入框，后续各段发给当前焦点，避免再次点击移动光标。真机 600 字三段输入，逐字回读一致。单次调用的输入超过时间预算（默认 90 秒，约 2,700 字）时返回 `input_complete=false` 和 `continue_token`，下一次只带 token 继续，不重发文本；期间执行过其他手机动作则续传失效。中途失败会报告已确认输入的字数。
- **batch 有时间预算。** 20 步的 batch 以前没有总时长上限；现在到达预算时在步骤之间停下，返回 `stop_reason="time_budget"`，从 `stopped_at` 继续。
- **预览不再被长调用冻住。** MCP 主循环原来逐行同步处理，widget 每 250 ms 的帧请求和模型的工具调用排在同一队列。现在读取线程直接应答帧请求、ping、目录和 widget 工具栏，手机工具在一个工作线程里保持严格顺序。推流线程原来每收到一块数据就重读并解析一次状态文件，现在按文件签名缓存。

## 单次请求

| 暖路径 | 0.1.14 | 0.2.0 |
| --- | ---: | ---: |
| selector 点击 | 5 | 3 |
| 坐标点击 | 2 | 1 |
| 默认滑动 | 2 | 1 |
| 替换输入完整文本 | 8 | 5 |
| 树观察 | 3 | 1 |

以上不含每次工具调用开头的锁屏检查。减少的来源：

- 元素查询开启 WDA 的非紧凑响应，一次返回类型、文字和位置，省掉单独的 rect 与 type 读取；WDA 不支持时自动退回逐项读取。
- 页面源码的根节点自带前台 App 的 bundle ID 和屏幕尺寸，读树时不再另问 `activeAppInfo`（真机约 135–198 ms）和 `window/size`（约 140–316 ms）；根节点尺寸与缓存不一致或缺少 bundle ID 时退回真实读取。
- 坐标动作复用 30 秒内的视口；传了 `observation_id`、每次观察、启动 App 或回主屏后重新读取。

没有改动的两处及原因：锁屏检查实测只需 4–5 ms，保留每次调用都查；`hittable` 是防止点到遮挡物的检查，保留。

## 实测后放弃的做法

- **加快滑动。** 现有手势每次 1.4–2.1 秒，是工具层最慢的单个动作。提高拖动速度或改用 W3C 触控序列能省 0.4–0.6 秒，但列表每次多滑 50%–100%（请求 306 点，实际 470–650 点），会让采集漏行；现有手势的位移是 296 点。保持不变。
- **复用预览视频帧当截图。** `/screenshot` 请求本身只有约 0.14 秒，省不了多少；而视频帧的画质（默认质量 25）和新鲜度都没有保证。
- **剪贴板粘贴长文本。** 真机上设置剪贴板需要把 WDA 切到前台，会打断目标 App 的焦点。
- **提高默认输入频率。** 400 字在 30 和 60 字/秒下都逐字一致（15.7 秒与 8.7 秒），但这只是一个输入框的结果，默认仍为 30；`WDA_TYPING_FREQUENCY` 可调。

## 度量

`wda_metrics` 现在给出每个工具的返回字节数（文本与图片分开）、每个 WDA 接口的次数 / 耗时 / 字节数，以及两次工具调用之间的等待时间：这段时间是宿主、模型和用户三者之和，正是以前看不到的大头。`reset=true` 开始新的统计窗口。`scripts/benchmark.py --run` 在“设置”里执行固定任务（打开并读页、滚动 10 页、采集列表、输入 600 字并清除、截图），只输出计数、字节数和耗时；手机锁屏或前台是其他 App 时拒绝执行。

可调项（环境变量，超出范围时使用默认值）：`WDA_SETTLE_SECONDS`（0–2，默认 0.8）、`WDA_CALL_BUDGET_SECONDS`（5–240，默认 90）、`WDA_TYPING_FREQUENCY`（5–120，默认 30）、`WDA_IMAGE=original`。

## 没有证明的事

模型回合数和端到端任务耗时没有用真实模型对照测量，本文不给出整项任务的提速比例。滚动任务在两次基准运行中页面状态不同，耗时不可直接比较。最后加入的几项改动（根节点替代两次读取、焦点输入、默认开启转场等待、工具栏动作）由自动测试覆盖，真机上只验证了它们依赖的事实；完整记录见 [validation.md](validation.md)。

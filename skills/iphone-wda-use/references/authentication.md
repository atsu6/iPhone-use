# 密码与 Face ID 认证接管

仅在当前观察或工具明确显示认证阻塞时请求用户接管。App 密码页、解锁码、验证码、Face ID / Touch ID 确认和登录续期都由用户在手机上完成。空控件树或黑色截图本身不足以证明正在认证；先根据当前提示区分锁屏、镜像占用、自绘内容与通道故障。

## 先区分阻塞层

| 当前证据 | 处理 |
| --- | --- |
| App 的登录 / 密码 / 生物识别提示 | 请求用户在该 App 内完成认证；暂停手机调用，随后重新观察目标页。READY 不能证明 App 已登录。 |
| `phone_locked` 或实际手机锁屏 | 请用户亲自解锁 iPhone、保持唤醒，完成后重验 READY 并观察目标 App。 |
| `local.pid.0` / `wda_foreground_unavailable` / XCTest Code 41 | 依照 setup skill 恢复 WDA 通道；不能当作 App 密码错误。只有系统确实要求信任或认证时才让用户完成对应操作。 |

## 交接时说明什么

发现明确认证阻塞时，先调用 `wda_screen(action="pause")`，停止 USB 预览采集并清空 widget 画面，再给用户接管提示。预览暂停状态不会因为重复 READY 或重新打开 widget 自动解除；接管期间保持暂停，不轮询帧、截图或用户输入。

简短说明当前 App、阻塞步骤、用户需要做的动作和随后继续的工作。可以用宿主可用的用户输入工具，给出“已完成，继续”及“暂时无法认证”选项；没有该能力时用清楚的等待说明，结束当前回合也必须保留“等待用户认证”的未完成状态。

示例：

> 招商银行当前需要 Face ID 或密码验证。请在 iPhone 上完成认证，并停留在账户页面；完成后回复“继续”。已读取的内容会保留，我会接着读取剩余明细。

只描述实际观察到的认证方式和页面，不猜测密码、PIN 或尝试绕过生物识别。不要要求用户将密码、解锁码或验证码发到聊天，也不要把凭据写进 `wda_type_text`、batch、日志、脚本或代码回退。即使密码框显示为普通 TextField，也由用户亲自输入；不只根据 SecureTextField 类型判断。

保留当前 App / 页面、已取得内容、已执行步骤、未完成项与动作执行边界，不要求为保存进度先逐步验收，也不记录认证凭据。接管期间暂停该 iPhone 的操作、观察和截图；可以整理已有结果及进度，不能轮询用户输入。Face ID 失败、要求改用密码或验证码过期时，让用户按手机实际提示处理，不能连续触发验证或反复重启 App / WDA。

## 认证完成后继续

只有收到用户明确完成通知后才调用 `wda_screen(action="resume")` 恢复预览；等待经过一段时间不等于完成或授权恢复。然后获取一次新观察，同时准备下一步并判断正确前台 App、认证提示及当前目标页。用户可能切换了 App、返回上层、滚动或顺带完成后续操作，因此不沿用接管前的坐标、observation_id 或元素 ID。根据新状态查找下一个语义目标；必要时用截图读取受保护页面内容，不为每步重新登录或单独验收。

如果认证仍未完成，指出当前剩余步骤并等待，不执行被阻塞动作。如果用户暂时不能认证，说明已完成和剩余范围，保留接管检查点；用户取消时停止后续操作。若手机或通道失效，按 setup skill 恢复 READY，直接复用其中的新观察继续准备下一步；不能把 App 会话过期误当成服务需要重启。

根据新状态继续剩余已授权工作。用户接管期间已完成的提交必须先回读结果，不能重复发送、支付、下单或重放整个输入 / 批次。认证完成不代表原任务完成；最终仍须核对全部 App、字段、覆盖范围和输出文件。

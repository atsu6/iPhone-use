# 完成条件应由任务定义

## 列表与详情

`wda_collect_list` 是页面采集器，不是任意 App 的业务模型。先确认当前列表和筛选范围；采集后保留第一页 / 最后一页边界、终止原因、去重规则与缺失字段。相同名称可能对应不同记录；交易记录优先用实际订单号、日期、状态和金额的组合去重，不能只按标签去重。

固定表头可能把下方元素遮住，即使树中仍然存在、矩形也在视口内。点击前核对截图和位置；详情打开后验唯一标题及关键字段，再接受数据。点击 HTTP 成功但页面仍旧时按 no_progress 处理。

遇到截图触发分享层，停止关闭后立即重复同一路径截图的循环。尽可能用树识别 / 关闭当前浮层并观察结果；只有核实 App 的新状态后继续。替代捕获方式、保护画面、应用内部数据导出需要另行可用能力，不能声称本插件已实现。

## 时效与汇总

对异步刷新，等待加载状态结束后重新读取实际内容。记录采集时间以及页面提供的估值、净值或成交日期；当天打开 App 不代表数据属于当天。

跨账户 / 币种分别记录，原币明细和账户总额不要重复相加。“待确认”“实扣成功”“份额已确认”分别是业务阶段；按用户要求定义成功，失败订单排除。现金、持仓、在途、未知账户保持明确归属，无法对账的差额保留未知。WDA 不负责估值、汇率换算或定义净资产。

写到外部数据库前，使用该服务的连接器检查字段类型和含义；错误或过时字段不能靠备注掩盖。写后读取新记录核对目标、正文、字段和重复条数。插件提供 iPhone UI 能力，没有通用 Notion / 文档 API。

## 输入与发送

合成测试可以用 `首字母 A +12.34 -5.67 中文测试；`，不使用用户的真实资产或账户信息。先测单行与短中文，核对 field value；再测试业务实际需要的长度和符号。工具返回已注入但字段不一致仍是输入失败。

对聊天草稿，记录输入前的会话和消息状态，输入后确保没有新消息，检查完整草稿，再独立发送一次。多行内容即使被显式允许，也可能有目标 App 的 Return 副作用。出现新增消息、乱码、部分发送或 timeout 时停下，读取真实会话，报告已发生结果，不能靠重新键入盲目补发。语言降级只能用于仍满足用户目标的文本，并保留正确内容；中文路径一次失败不代表全局不支持中文。

## 计时与可追溯性

工具返回的 observation ID 与独立截图连接动作和观察；默认保留最近 100 张图片，较旧图片会清理，重要验收证据需在清理前保留到用户指定的本机结果目录。XML 与动作参数没有自动持久保存为完整轨迹。metrics 只在当前 MCP 进程中保留有界的请求 / 工具计时，不含输入文本与业务值。没有完整日志时明确证据缺口，不把摘要里的“completed”扩展为业务成功。用户要求记录完整轨迹时，仅在其本机记录必要证据并排除 Git。

评测分开记录首次部署、功能预检、业务任务和报告生成。HTTP 总耗时、UI 动作次数、工具调用和任务墙钟属于不同口径。模型响应链、工具调度、解析和文件操作的间隙不能只靠 HTTP 账本分拆；需要相应计时证据。减少工具回合后仍要测量端到端耗时和交付完整度。

# 密码与 Face ID 的用户接管

仅在当前截图或明确工具错误显示真实认证阻塞时请求用户接管。App 密码、PIN、验证码、Face ID / Touch ID、手机解锁和登录续期由用户在手机完成。黑屏、保护截图或读取失败本身不足以确定认证；依据实际画面与通道错误区分。

| 当前证据 | 处理 |
| --- | --- |
| App 的登录 / 密码 / 生物识别提示 | 请用户在当前 App 内完成，暂停手机调用；通知后新截图核对目标页。READY 不证明 App 已登录。 |
| phone_locked 或实际锁屏 | 用户亲自解锁并保持唤醒，通知后重验 READY 和 App 截图。 |
| local.pid.0 / wda_foreground_unavailable / XCTest Code 41 | 按视觉 setup skill 恢复通道；不能归因 App 密码错误。只有系统实际要求确认时才让用户完成对应操作。 |

简短说明实际 App、阻塞步骤、用户要完成的认证，以及通知“继续”后待恢复的工作。例如：

> 当前 App 要求 Face ID 或密码验证。请在 iPhone 上完成认证并停留在目标页面，完成后回复“继续”；我会保留已核验进度，接着完成剩余读取。

不要猜密码、反复尝试或绕过生物识别。不得要求用户把密码、解锁码或验证码发送到聊天，也不得放入 `wda_vision_type_text`、batch、日志或回退代码。即使画面看起来是普通文本框，实际用于认证也交给用户。

保留 App / 页、已核验进度、未完成项、待继续步骤及已执行但未核验的动作，不记录凭据。接管期间暂停该 iPhone 的全部动作、读取、XML 和截图；可以整理已有结果。不要轮询用户输入、反复启动认证、Home、launch 或重启 WDA。等待超时和没有回复都不是完成通知；没有等待工具时明确保留“等待用户认证”的未完成状态。

用户明确通知完成后调用 `wda_vision_observe`，看当前 App、提示是否消失及目标页，从当前图定位。用户可能滚动、切换 App 或完成后续提交，先看实际结果再决定剩余动作，不重放整段输入 / batch，不重复发送、支付或下单。

认证仍未完成则指出实际剩余步骤并等待；用户取消则停止。手机锁屏或通道失效时先恢复 READY，App 认证本身不需要重建服务。认证完成只是解除阻塞，原任务全部 App、字段、覆盖范围和最终交付仍须核验。

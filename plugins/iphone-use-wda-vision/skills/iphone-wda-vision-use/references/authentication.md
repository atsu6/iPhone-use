# 密码与 Face ID 的用户接管

仅在当前截图或明确工具错误显示真实认证阻塞时请求用户接管。App 密码、PIN、验证码、Face ID / Touch ID、手机解锁和登录续期由用户在手机完成。黑屏、保护截图或读取失败本身不足以确定认证；依据实际画面与通道错误区分。

| 当前证据 | 处理 |
| --- | --- |
| App 的登录 / 密码 / 生物识别提示 | 暂停手机调用，用提问工具请用户在当前 App 内完成；收到真实完成答复后新截图核对目标页。READY 不证明 App 已登录。 |
| phone_locked 或实际锁屏 | 用提问工具请用户亲自解锁并保持唤醒，收到真实完成答复后重验 READY 和 App 截图。 |
| local.pid.0 / wda_foreground_unavailable / XCTest Code 41 | 按视觉 setup skill 恢复通道；不能归因 App 密码错误。只有系统实际要求确认时才让用户完成对应操作。 |

## 用提问工具等待用户完成

优先调用当前宿主可用的 `functions.request_user_input_async`；它可在 Default 模式显示问题并立即返回，用户答复会作为后续输入到达。不要只发一段说明让用户自行回复“继续”。问题标题要完整说明实际 App、阻塞步骤、用户要在手机完成的操作，以及完成后待恢复的工作。第一个选项必须原样为「已完成继续」，第二个为「暂时无法完成」；不添加推荐后缀，不询问密码或验证码本身。

例如，实际画面已显示 Face ID 时调用：

```json
{"questions":[{"title":"当前 App 需要 Face ID 验证。请在 iPhone 上完成并停留在目标页面；完成后选择「已完成继续」，我会接着读取剩余明细。","options":["已完成继续","暂时无法完成"]}]}
```

按当前证据把示例中的 App、认证类型和剩余工作替换为实际内容。密码、手机解锁、信任确认或登录续期也使用这个流程。只有异步提问工具不可用时，才使用当前实际可用的宿主提问工具；遵循其 schema，并保持相同选项顺序。所有提问工具均不可用时，才用聊天明确说明阻塞、请用户亲自完成后回复「已完成继续」，并保留等待用户认证的未完成状态。不要为调用提问而切换模式或编造不存在的工具。

发出问题后保留待答状态。异步工具立即返回、按钮预选、经过一段时间或没有回复都不表示用户已完成。只有用户实际选择「已完成继续」或明确回复已完成后，才恢复手机调用。用户选择「暂时无法完成」时继续保留阻塞与进度；用户明确取消时停止。等待期间可以整理已有结果或推进不依赖该手机的工作，不以最终回答把未完成任务当作结束，不重复弹出同一问题。

不要猜密码、反复尝试或绕过生物识别。不得要求用户把密码、解锁码或验证码发送到聊天，也不得放入 `wda_vision_type_text`、batch、日志或回退代码。即使画面看起来是普通文本框，实际用于认证也交给用户。

保留 App / 页、已核验进度、未完成项、待继续步骤及已执行但未核验的动作，不记录凭据。接管期间暂停该 iPhone 的全部动作、读取、XML 和截图。不要轮询用户输入、反复启动认证、Home、launch 或重启 WDA。

用户明确通知完成后调用 `wda_vision_observe`，看当前 App、提示是否消失及目标页，从当前图定位。用户可能滚动、切换 App 或完成后续提交，先看实际结果再决定剩余动作，不重放整段输入 / batch，不重复发送、支付或下单。

认证仍未完成则指出实际剩余步骤并等待；用户取消则停止。手机锁屏或通道失效时先恢复 READY，App 认证本身不需要重建服务。认证完成只是解除阻塞，原任务全部 App、字段、覆盖范围和最终交付仍须核验。
